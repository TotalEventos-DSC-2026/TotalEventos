# Artefato 10 — Roteiro operacional de configuração no GitHub

## Objetivo

Orientar a equipe na criação do planejamento do projeto no GitHub, seguindo a sequência correta de criação e organização de Issues, labels e Project Board.

## Passo a passo

1. Acessar o repositório do projeto em `https://github.com/<usuario>/<repositorio>`.
2. Criar a Issue principal, representada pela Epic `UC01`.
3. Inserir na descrição da Epic: objetivo, contexto, requisitos, dependências e critérios gerais de aceite.
4. Criar as Sub-Issues `SUB-01` a `SUB-07` com títulos e descrições detalhadas.
5. Vincular cada Sub-Issue à Epic principal por meio de referência direta (`#<numero-da-epic>`) ou checklist na descrição.
6. Inserir critérios de aceite e evidências esperadas em cada Sub-Issue.
7. Criar as labels definidas no plano de labels.
8. Aplicar labels às Issues e Sub-Issues com consistência funcional, técnica e de prioridade.
9. Criar o GitHub Project com o nome desejado para o roadmap do projeto.
10. Configurar os 5 estados exatos do board: `Backlog`, `Ready`, `In Progress`, `In Review`, `Done`.
11. Adicionar as Issues e Sub-Issues ao Project.
12. Distribuir os responsáveis e confirmar o estado inicial de cada item.
13. Revisar o board para confirmar que a rastreabilidade e as dependências estão consistentes.
14. Comentar no repositório ou em reuniões de alinhamento quaisquer bloqueios ou dependências críticas.

## Checklist de finalização

- [ ] Epic criada;
- [ ] Sub-Issues criadas;
- [ ] Issues vinculadas à Epic;
- [ ] Labels aplicadas;
- [ ] Board configurado com os 5 estados exigidos;
- [ ] Responsáveis definidos;
- [ ] Rastreabilidade validada;
- [ ] Dependências verificadas.
